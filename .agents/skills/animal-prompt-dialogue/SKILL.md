# 動物Prompt対話作成

Farmwareの動物スプライト用テンプレートを、初心者でも答えやすい短い対話からコピー可能な英語Promptへ変換する。

## 最初に読む資料

1. Farmwareリポジトリ内で作業しており、`Docs/Art/TilemapSpriteProductionChecklist.md`が存在する場合は、同文書の「動物スプライト共通フォーマット」を読む。これを最新の正とする。
2. リポジトリ文書を参照できない場合、または必要な角括弧と計算規則を確認するときは、[references/template.md](references/template.md)を読む。

文書と参照ファイルが異なる場合は、Farmwareリポジトリの文書を優先する。差異が最終Promptへ影響する場合だけ、ユーザーへ短く知らせる。

## 対話の進め方

- 会話内ですでに確定している値を再質問しない。
- 未確定項目を一度に並べず、原則として一問ずつ日本語で質問する。
- 質問には、何を決める項目かが分かる短い説明と、必要なら1つの具体例を添える。
- ユーザーが「おまかせ」と答えた項目は、動物種として自然で、共通ルールと矛盾しない最小限の内容を選ぶ。
- ユーザーが必要情報を最初からすべて提示した場合は、確認質問を省略して完成結果を出す。

次の順で不足情報を集める。

1. `Animal`と、必要なら安定した`Animal ID`。
2. PixelLabで選ぶ`Output size`。Create S-XL Image (Pro)が返す総フレーム数は`Output size`の最大辺から自動計算し、ユーザーには質問しない。`Output size`と総フレーム数は設定一覧と計算には使うが、完成Prompt本文には絶対に書かない。
3. 共通4ポーズ以外の`Species-specific Poses`。先にスキル側から、その動物らしい候補と枚数への影響を提案し、ユーザーに採否を選んでもらう。適切な候補がなければ`None`を推奨する。
4. `Species Features`。その動物だと判別するために残す身体特徴だけを扱う。
5. `Species-specific Pose Requirements`。移動、採食、休息や固有ポーズを、その動物の体型に合わせて記述する。
6. `Species-specific Prohibitions`。誤生成されやすい身体特徴や小物だけを追加する。種固有の禁止事項がない場合は空とし、完成時にテンプレートの角括弧プレースホルダーだけを削除する。直前の共通禁止文は削除しない。

次の項目は全動物共通のため質問しない。

- 必須ポーズは`idle`、`move`、`eat`、`sleep`。
- 画角は左向きの斜め横（left-facing three-quarter side view）に固定する。正面より横向きに近い角度とし、頭と胴体をともに画面左へ向ける。顔の特徴を読める範囲だけ頭をわずかに手前へ振ってよいが、頭をカメラ正面へ向けず、正面向きの構図にしない。向きはユーザーへ質問しない。
- `idle`、`move`、`eat`と動物種固有ポーズの目はシンプルな黒い縦長とし、`sleep`では両目を閉じる。全ポーズで白目、ハイライト、まつ毛、複雑な表情を付けない。
- 鈴、帽子、バンダナ、首輪などの装飾品を付けない。
- ソフトブラック`#333333`の実線輪郭、左上光源、透明背景、地面Tileなし、投影影なし。
- 同じ基本バリエーションでは、`sleep`で両目を閉じること以外、ポーズ間で表情、目、毛色、模様、体格、画角、向き、縮尺、パレット、輪郭を変えない。

## 動物種固有ポーズの提案

`Output size`が決まった後、共通4ポーズ以外に追加する価値がある静止ポーズを検討する。

- その動物を識別しやすくする習性や身体動作から、0～3件に絞って提案する。
- 選択中の`Output size`でもシルエットだけで読み取れる単純なポーズを優先する。
- `idle`、`move`、`eat`、`sleep`と意味や見た目が重複する候補は出さない。
- 表情、目、毛色、模様、体格、左向きの斜め横画角、頭と胴体の左向き、縮尺、パレット、輪郭を変えず、身体の姿勢だけで表現できる候補に限定する。
- 餌、容器、寝具、道具、装飾品、エフェクト、文字など、外部の小物がないと読めない候補は出さない。
- ゲーム仕様で未定義の生産、攻撃、繁殖、負傷などを暗黙に追加しない。
- 有用な候補がなければ、数を埋めるために提案せず「固有ポーズなし」を推奨する。

各候補は、英語の`Pose ID`、日本語の短い説明、追加後の`Pose Count`、`Base Variation Count`、`Unused Frames`を示す。複数候補を同時採用した場合の枚数も必要なら併記する。最後に、採用する候補または「なし」を一問で確認する。ユーザーの選択前に固有ポーズを確定しない。

## 計算と配置

- PixelLabの`Create S-XL Image (Pro)`を使用する。
- `Max Dimension = max(Output Width, Output Height)`として、次のPixelLab公式サイズ帯から`Total Frames`を決める。
  - `16～42 px`: 64 frames。
  - `43～85 px`: 16 frames。
  - `86～170 px`: 4 frames。
  - `171 px以上`: 1 frame。上限はPixelLabが各アスペクト比で許可する最大寸法に従う。
- `256 ÷ Output Width`や`256 ÷ Output Height`では計算しない。出力シートのgrid寸法と非正方形の配置はPixelLab出力に従う。
- `Pose Count = 4 + 動物種固有ポーズ数`。
- `Base Variation Count = floor(Total Frames ÷ Pose Count)`。
- `Unused Frames = Total Frames - Base Variation Count × Pose Count`。
- `Total Frames < Pose Count`の場合は、一度の生成で全必須ポーズを持つ基本バリエーションを作れない。完成Promptを出さず、より小さい`Output size`または固有ポーズ数の削減をユーザーへ提案する。
- Promptでは、各基本バリエーションの全ポーズを`idle, move, eat, sleep, 固有ポーズ...`の順でひとまとまりにするよう指定する。`Output size`、1Spriteの画像寸法、出力シートのgrid寸法、総フレーム数、基本バリエーション数、出力シート上の行列配置は書かない。
- 余りフレームがある場合は、末尾だけを透明な未使用フレームにする一般指示をPromptへ入れる。採用Spriteの各ポーズ比率は均等なままにする。

例として、`Output size: 32×32`は最大辺32 pxなので総出力64 framesとなる。共通4ポーズだけを使う場合は、16基本バリエーション、未使用0 framesとなる。これは寸法の固定規則ではない。

## 完成時の出力

すべての値が揃ったら、次を日本語で簡潔に出力する。

1. `設定`: 動物、PixelLab tool、Output size、`No Background: enabled`、最大辺、総フレーム数、ポーズ、基本バリエーション数、未使用フレーム数。
2. `PixelLab Prompt`: 英語の完成Promptを1つの`text`コードブロックで出す。

完成Promptでは次を必ず満たす。

- 角括弧、TODO、未解決の選択肢を残さない。
- 一度の生成で、全基本バリエーションと全ポーズを作るよう明記する。
- 同じ基本バリエーション内で、ポーズ以外の見た目を変えないよう明記する。
- 各基本バリエーションの全ポーズをひとまとまりにし、ポーズ種類ごとに全バリエーションをまとめないよう明記する。
- `Output size`、1Spriteの画像寸法、出力シートのgrid寸法、総フレーム数、基本バリエーション数、出力シート上の行列配置をPrompt本文へ書かない。画角を示す`orthogonal square grid`と、基本バリエーション内のポーズ順序は含める。
- 種固有の禁止事項が空の場合は`[SPECIES-SPECIFIC PROHIBITIONS]`だけを削除し、同じ段落の共通禁止文を残す。
- すべての動物を正面より横向きに近い左向きの斜め横から描き、頭と胴体をともに画面左へ向け、頭をカメラ正面へ向けない指示を含める。
- 通常ポーズでは黒い縦長の目、`sleep`では閉じた両目にする規則と、装飾禁止、輪郭、光源、透明背景の規則を含める。

Promptの作成だけが依頼されている場合、画像生成、ファイル編集、UnityへのImport、commitは行わない。
