## 1. 目的と優先順位

座標由来のバイオームを持つ地上世界で、採掘・埋立・建築により環境を変更し、海中・深海も探索できるようにする。バイオームはMinecraft、タイル編集はCore Keeper、部屋と施設はドラゴンクエストビルダーズの考え方を基準にする。個別作品の完全再現を要求するものではなく、Farmwareの合意済み仕様を優先する。

「自然生成の基礎データ」「現在の有効地形」「描画用レイヤー」を分離する。生態、移動、採掘、配置、保存は現在の有効地形を参照し、Tilemapの絵や元の生成結果だけで判定しない。

## 2. 実装済み基盤と移行対象

基準HEADはPR #23のmerge commit `d8835670`。実装済み範囲と移行先は次のとおり。

| 領域 | 現在の実装 | 改訂後 |
| --- | --- | --- |
| 座標・チャンク | int絶対座標、64×64／16×16、負座標・端点対策 | 再利用し、キーにWorldLayerを追加 |
| 生成 | 決定論的7バイオーム、地面・水・マグマ・単一岩壁、木・石・砂 | 気候生成を再利用し、複数ブロック・3レイヤーへ拡張 |
| 開始探索 | 12×8建築可能領域、中心3×3、近傍の木・石・水を要求 | 許可バイオームと安全な出現座標を探索。コア・平地・資源保証は撤回 |
| 地形ルール | `GeneratedTile`の地形属性と`TerrainPlacementRules` | 元生成＋変更差分の有効セルと、移動能力別ルールへ拡張 |
| 動物 | 鶏定義、独立Seed、64×64地域初期個体群、全個体ID、診断 | 既存鶏を保持し、永続／匿名遭遇、環境・時間条件、回復へ拡張 |
| 表示 | 9枚のTilemap、岩壁影、チャンク別表示・プール、Floating Origin | 土地寸法等を再利用。ブロック定義参照、穴、下層プレビュー、照明を追加 |
| 保存・ゲーム操作 | ディスク保存、直接操作プレイヤー、採掘・設置は未実装 | 新しいデータ契約を先に定め、機能ごとに保存も実装 |

v1のノイズ値、マグマ40〜60%候補、岩壁10〜18%候補、木・石・砂の密度、初期スポーン条件、Sprite寸法・描画順は[旧実装記録](./RandomMapGenerationSpecification_v1_Archive.md)で確認できる。そのうち初期スポーン、単一階層、無限地質資源、未捕獲個体の一律永続化、生成バージョン混在は今後の規則として使わない。

## 3. 座標とワールドレイヤー

| キー | 内容 |
| --- | --- |
| ワールドセル | `(WorldLayer, TileX, TileY)`。TileX/Yは符号付き整数 |
| チャンク | `(WorldLayer, ChunkX, ChunkY)`。1辺64タイル |
| ローカルセル | X/Y各0〜63 |
| サブチャンク | 1辺16タイル、1チャンクに16個 |
| ワールドレイヤー | `None = 0`を予約し、`Surface = 1`、`Underwater = 2`、`DeepSea = 3`を固定保存IDとして使用 |

- 層を追加するために既存X/Yの範囲を縮めたり、ハッシュへ無検証でbitを詰め込んだりしない。
- 負座標には床方向の除算を使う。距離・差・端点は64bit中間計算で検査する。
- Transformのfloat、カメラ位置、EntityのIndexを生成・保存キーにしない。
- Floating OriginはPresentationだけを移動し、絶対座標とレイヤーは変えない。
- 同じX/Yでも異なるレイヤーの占有、部屋、資源、個体、差分を混同しない。

## 4. Seedと生成バージョン

- 任意の数値・文字列Seedを受け付け、空欄は生成した文字列を表示する。安定した内部Seedへ変換する。
- 基礎生成はSeed、GeneratorVersion、保存した生成設定、レイヤー、絶対座標、用途別Salt、候補番号から決める。
- `UnityEngine.Random`、`string.GetHashCode()`、Transform、ロード順、Job完了順を乱数入力にしない。
- 用途別Saltを固定し、ブロック種類や装飾の追加で別用途の乱数列を消費しない。
- `AnimalPopulationSeed`は新規ワールドで一度だけ地形Seedと独立に生成して保存する。
- ワールド作成時のGeneratorVersion・設定をワールド全体に固定する。更新後の未生成チャンクにもその版を使う。生成済み・未生成チャンクを自動で新旧混在させない。
- サポートする旧生成器・設定解決を維持し、廃止が必要なら明示的な移行を別途設計する。
- 初期開発中は既存方針に従ってGeneratorVersion 1のまま調整できるが、開発用ワールドの互換性を保証しない。新旧データを誤って受理しないため、保存スキーマ識別・検証を技術仕様に従って持つ。
- `GeneratedWithVersion`はワールド版との整合を検証する用途に使える。旧`GenerationUpgradeEpoch`と境界ブレンディングは新計画に含めない。

## 5. バイオームとブロック構成

初期の7バイオーム、草原、森林、砂漠、岩地、湿地、雪原、火山を気候ノイズ・適性スコア生成の基礎として再利用する。海は現在の設計では水域であり、海バイオームへの変更は今回の合意には含めない。生態の差は水域タグ・レイヤー・環境条件でも表現する。

- 気温、湿度、標高、Weirdness等から複数チャンクへ連続する領域を作る。既存の固定小数点ノイズと用途別Saltを再利用する。
- 同心円、初期地点からの距離、研究ランク、装備でバイオームを変えない。
- バイオームIDは固定の地域情報。地面や壁を別の素材へ置換しても変化しない。
- バイオームごとの地面・壁パレットと、地層・鉱床・局所パッチ用ノイズを分ける。1バイオーム1ブロックに固定せず、無関係なセルごとの市松抽選にもさせない。
- ブロック定義は定義GUID、硬度、回収アイテム、移動・設置・水密・施設境界属性、表示参照を持つ。
- 境界の補間は座標由来の値から計算し、既に生成した隣接チャンクへ依存しない。
- 多層生成を追加しても、既存地上の結果を変える必要がない箇所は維持する。必要な変更は生成署名・分布監査・デバッグ表示の差として記録する。

## 6. 有効セルと編集

| データ | 寿命・責務 |
| --- | --- |
| バイオーム・自然環境 | Seedと座標から再生成。人工ブロックと分離 |
| GroundBlock | 掘削・埋立できる地面。なしなら空洞／穴 |
| WallBlock | 採掘・設置できる壁。地面とは別の占有 |
| Liquid | 地面がないセルの水種・マグマ。なしも許可 |
| Surface | 舗装、床、耕地などの表面状態 |
| 自然資源・植生 | 木、石、植物等の個別状態・生成差分 |
| 配置物 | 橋、扉、家具、設備等の独立状態・参照 |

これは論理データ境界であり、全セルを個別Entityにする要求ではない。Buffer・配列等の格納形式は計測で決める。

- 元生成結果を破壊せず、変更差分を適用して現在の有効セルを得る。元と一致する差分は除去できる。
- 自然生成壁・設置壁とも採掘可能で、必要道具硬度を検証する。地面・壁の回収と設置は原則1:1。
- 地面を掘った空セルへ液体がなければ空の穴になる。同レイヤーの地面と液体を重複保持しない。
- 支えのない壁・設備、上層配置物のある地面・橋の変更などは、変更後の有効セルと依存関係をCommandで検証する。落下・崩落を暗黙に発生させない。
- 変更はアイテム消費・回収、耐久消費、占有、液体予定、施設・生態Dirtyを含め整合させる。失敗時は部分変更しない。
- 境界セルの編集は隣接サブチャンク・チャンクのハイライト、岩壁影、通行キャッシュにもDirtyを伝える。
- 未ロード隣接セルも、生成＋保存差分から読み取る。境界の見た目や生態で基礎生成だけを再サンプルして編集を無視しない。

## 7. 液体の伝播と反応

液体は有限の水量・水圧・流速を持つ物理流体ではない。穴が辺接続すると固定Tick上で伝播する。斜め接触だけを接続とするか等の細則はTERRAIN-02Aで固定する。

- 水1セルやバケツから広がり、取り出しても有限残量として枯渇しない。
- 埋立で当該セルの液体を除去し、再掘削時は空にする。近隣に液体があれば流入する。
- 水種の置換は明示的な全順序で、マグマとの接触は反応表で処理する。反応物、対象セル、競合時の順序を定義する。
- 自然生成の海とマグマの隣接は現行生成にもある。生成時の接触とプレイヤー操作後の反応をどう整合させるかを、無限反応・沿岸崩壊が起きない例で確認する。
- WorldLayerと絶対座標で安定した処理順を作る。処理予算を分割しても、同じ論理入力とTickから結果を再現可能にする。
- 未ロード先への境界要求・保留キューを保存し、表示のアンロードで伝播が消えたり永遠に止まったりしない。
- ただし無限世界全域を毎Tick生成しない。伝播の作業集合と予算、未生成領域の需要生成、過大処理時の継続方法を設計する。
- 睡眠やオフライン経過ではキューを消費しない。画面外でも稼働中SimulationTickで進める。
- 橋は液体を消さない。排水装置や水密扉は液体と部屋状態に明示的に関与する。

## 8. 多層水域

地上・海中・深海の同X/Yで隣接レイヤーへ移動する。入口オブジェクトは要求せず、固定保存IDと判定順は[WORLD-01B製品契約](../Development/World01BMultiLayerWaterContract.md)に従う。

固定3層は論理的に常に存在し、未掘削セルは`Solid`として扱う。レイヤー移動は、遷移元・先の開放水域、移動先の通行・衝突、装備を検証する。単に地上セルが歩行可能という理由で海底の土や空気室へ通過させない。未ロード先も論理的には存在するため、ロード／生成してから検証する。

川、池、沿岸を含む自然水域はUnderwaterまで水とする。DeepSeaは`WaterBodyType.Sea`のうち、Seed・GeneratorVersion・保存設定・絶対座標・用途別Saltから決定論的に選ぶ沖合だけに生成し、川・池には生成しない。沖合の具体的なノイズと閾値は自然3層生成の接続時に分布監査して決める。

地上から1階層掘ると同じX/YのUnderwater空間を作り、上層が水なら同じ固定Tickの移動判定前に自動浸水する。UnderwaterからDeepSeaを掘る場合も同じとする。通常の上下遮断は変更差分適用後の上層地面・下層天井から導出し、その後に閉じた水密配置物を合成する。独立した上下接続フラグは保存しない。上層を閉じても下層の既存水は消さず、排水施設が成立するまで保持する。

水密室は排水施設が成立している間、外水への水平扉を開けても乾燥を維持する。排水なしで開けば同じ固定Tickの移動判定前に浸水し、密閉だけでは既存水を除去しない。潜水・浮上は水同士に限定し、水中から直下の乾燥室へは移動しない。乾燥室へは同じレイヤーの水平扉から出入りする。排水設備の具体構成はFAC-02B、液体伝播の予算とキューはTERRAIN-02Aで決める。

プレビューは直下1層を簡略表示する。上の地面や不透明壁を透視せず、未発見生物の図鑑登録や遠隔操作を発生させない。描画のためのプレビュー常駐と、個体群・施設等のSimulation処理を区別する。

## 9. 開始地点の選択

- `BiomeDefinition.AllowInitialSpawn`相当の設定を開発者が変更できる。雪原・火山等を除外可能にする。
- 原点周辺から座標順・距離順など固定した優先順位で、地上の許可バイオーム内の有効地点を探す。
- プレイヤーの占有を満たす通行可能セルで、壁・液体・資源・設備内へ埋まらないことを検証する。
- コア、一定の平地面積、資源までの距離、低い敵密度・希少度は選択条件にしない。周辺に禁止バイオームがあることは許可する。
- 探索範囲を有限の段階で広げ、進捗を表示する。全バイオーム禁止、候補なし、座標限界では明示的な失敗として返す。Scene保存座標へゲーム開始するフォールバックは使わない。
- 選定した初期位置は保存し、ロード時に再探索しない。死亡時の救済は現在の地形を検証する。
- 旧12×8・中心3×3テストは歴史的な実装保証として扱い、変更PRで新条件のテストへ置換する。

## 10. 生物・植物・資源と環境

- 野生生物は固定Biome＋現在地形・液体・植物・明るさ・時間帯・天候・屋内等から候補を得る。
- 種×レイヤー×地域の収容数、現存数、回復・移入予定、抽選状態を保持する。現在の地域単位64×64は再利用候補とする。
- 永続個体と匿名遭遇を分け、個体群からの出現・退避と、捕獲・討伐による減少を別の会計にする。
- 捕獲済み・命名・追跡等は個体IDを維持する。表示のアンロードや時間帯変更で消失・再抽選しない。
- 回復は固定Tick上で進め、環境が回復すればゼロから再定着できる。睡眠で回復させない。
- 通常の敵の強さや出現を開始地点の距離、研究、工場規模で一律補正しない。未ロード拠点の構造破壊は発生させない。
- 木・植物は成長と種子等で増え、根を残した採集では再成長可能。鉱石・化石・地形ブロックは有限で再生成しない。
- 設置ブロックは固定バイオームを変更しないが、飼育・栽培・生息条件を変更できる。

## 11. 読み込みと表示

現行の `Unrequested → Queued → GeneratingData → ReadyToApply → Active → Inactive → Unloaded` は表示・生成の段階として再利用する。`Active`は個体や工場の生存条件ではない。

- プレイヤーの移動・衝突・潜水先、カメラ表示、下層プレビュー、稼働施設・液体の要求を区別して集約する。
- 高速車両・ヘリを想定し、速度・方向に応じた先読みを計測する。未完成セルへ進入しない制御を用意する。
- カメラだけを遠くへ動かす診断操作で、図鑑や生態進行を獲得しない。
- 地形生成のJobと確定公開の固定Tick境界は現行の決定論保証を保つ。停止中の地形準備で個体群・IDを進めない。
- 現在の512タイル原点変更、先行表示1、生成プリロード1、保持余白1、同時生成2、反映消去4、プール8は既存カメラ検証時の値。車両・3層の合格値には流用しない。
- 通常速度12／高速36タイル毎秒は現行診断カメラの比較条件であり、歩行や車両の確定速度ではない。
- 土地16×24、岩壁16×28、論理セル16×16、液面8px投影、基準480×270を既存アート基盤として再利用する。新ブロックはBiomeではなくBlock定義から表示を選ぶ。
- 夜は照明の暗さで表現し、追加の視界半径制限を行わない。生物の発見判定と表示の視認性を一致させる境界を検証する。
- 表示の影・外周キャッシュは現在の有効地形を参照するよう更新する。元生成専用のHaloで編集済みの隣接壁を復元しない。

## 12. 保存

ワールドヘッダーはWorldId、Seed、GeneratorVersion、生成設定、初期位置、次回ID、SimulationTick、WorldClock、個体群Seed、地域天候の再現情報を持つ。

変更データはレイヤー＋チャンク＋サブチャンクで、地面、壁、液体、地表、除去済み資源、植生成長、配置物、液体保留要求を保存する。未変更地形は固定版で再生成する。表示・Halo・通行索引等は再構築する。

個体・個体群、施設、設備、物流、ドロップ、乗り物は所有者と安定IDに従い一度だけ保存する。跨ぐチャンクへ複製しない。プレイヤーの位置はレイヤー、整数セル、セル内連続位置を分けて保存する。死亡品の絶対消失Tickを保持し、未ロードで期限切れなら再生成しない。

## 13. デバッグと検証

実装変更と同じPRでEditor可視化、Map Viewer、凡例、中央タイル情報、分布監査、関連テストを更新する。新モードを追加しただけで既存通常表示が一致しない状態を完了にしない。

- F3/F4に現在レイヤー、絶対座標、初期位置を接続する。
- Editorで基礎生成／変更後地形、地面／壁／液体／穴、固定Biome、スポーン許可、通行能力別可否、液体キュー、生態収容数を確認できるようにする。
- Map Viewerは「自然生成」と「実ワールド差分込み」を明示し、未ロード差分を無視した自然生成を現在地形と誤表示しない。
- 同Seed・設定・Layer・座標の結果、異なる生成順、Job条件、チャンク境界、負座標、int端点を検証する。
- 編集→往復→保存→ロードで地形・資源・水・個体・IDが一致することを検証する。
- 全禁止スポーン、候補なし、初期地点に隣接する危険バイオームを確認する。周辺難易度を変えない。
- 水のない穴、埋立→再掘削、異種液体、反応連鎖、未ロード境界、予算分割、上下遷移失敗を検証する。
- 時刻ジャンプで地形・個体群回復・液体・死亡期限が進まないことを検証する。
- 表示のアンロードとSimulation稼働を分け、個体の重複、野生個体群の水増し、遠隔設備の停止を検出する。
- プレイヤー、動物、車両、3層プレビューを段階追加したDevelopment BuildでCPU/GPU/GC/メモリを計測する。製品最大Viewportや合格FPSを独自に設定しない。

具体的な現在のテスト・メニューは[テスト](../Development/Testing.md)と[Editorツール](../Development/EditorTools.md)を参照する。旧テストの成功は改訂後の未実装機能の検証済みを意味しない。
