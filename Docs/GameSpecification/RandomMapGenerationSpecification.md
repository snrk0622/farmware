## 1. 目的と優先順位

座標由来のバイオームを持つ地上世界で、採掘・埋立・建築により環境を変更し、海中・深海も探索できるようにする。バイオームはMinecraft、タイル編集はCore Keeper、部屋と施設はドラゴンクエストビルダーズの考え方を基準にする。個別作品の完全再現を要求するものではなく、Farmwareの合意済み仕様を優先する。

「自然生成の基礎データ」「現在の有効地形」「描画用レイヤー」を分離する。生態、移動、採掘、配置、保存は現在の有効地形を参照し、Tilemapの絵や元の生成結果だけで判定しない。

## 2. 実装済み基盤と移行対象

基準HEADはPR #23のmerge commit `d8835670`。実装済み範囲と移行先は次のとおり。

| 領域 | 現在の実装 | 改訂後 |
| --- | --- | --- |
| 座標・チャンク | int絶対座標、64×64／16×16、負座標・端点対策、WorldLayer付きセル・チャンク・要求・索引 | WORLD-01Cで接続済み。Surface結果を維持し、別層自然生成はTERRAIN-01Cで追加 |
| 生成 | 決定論的7バイオーム、地面・水・マグマ・単一岩壁、木・石・砂 | 気候生成を再利用し、複数ブロック・3レイヤーへ拡張 |
| 開始探索 | 12×8建築可能領域、中心3×3、近傍の木・石・水を要求 | 許可バイオームと安全な出現座標を探索。コア・平地・資源保証は撤回 |
| 地形ルール | `GeneratedTile`の地形属性と`TerrainPlacementRules` | 元生成＋変更差分の有効セルと、移動能力別ルールへ拡張 |
| 動物 | 鶏定義、独立Seed、64×64地域初期個体群、全個体ID、診断 | 既存鶏を保持し、永続／匿名遭遇、環境・時間条件、回復へ拡張 |
| 表示 | 9枚のTilemap、岩壁影、チャンク別表示・プール、Floating Origin | 土地寸法等を再利用。ブロック定義参照、穴、下層プレビュー、照明を追加 |
| 保存・ゲーム操作 | ディスク保存、直接操作プレイヤー、採掘・設置は未実装 | 新しいデータ契約を先に定め、機能ごとに保存も実装 |

v1のノイズ値、マグマ40〜60%候補、岩壁10〜18%候補、木・石・砂の密度、初期スポーン条件、Sprite寸法・描画順は[旧実装記録](./RandomMapGenerationSpecification_v1_Archive.md)で確認できる。そのうち初期スポーン、単一階層、無限地質資源、未捕獲個体の一律永続化、生成バージョン混在は今後の規則として使わない。

## 3. 座標とワールドレイヤー

| キー | 内容 |
| --- | --- |
| ワールドセル | `(WorldLayer, TileX, TileY)`。TileX/Yは符号付き整数 |
| チャンク | `(WorldLayer, ChunkX, ChunkY)`。1辺64タイル |
| ローカルセル | X/Y各0〜63 |
| サブチャンク | 1辺16タイル、1チャンクに16個 |
| ワールドレイヤー | `None = 0`を予約し、`Surface = 1`、`Underwater = 2`、`DeepSea = 3`を固定保存IDとして使用 |

- 層を追加するために既存X/Yの範囲を縮めたり、ハッシュへ無検証でbitを詰め込んだりしない。
- 負座標には床方向の除算を使う。距離・差・端点は64bit中間計算で検査する。
- Transformのfloat、カメラ位置、EntityのIndexを生成・保存キーにしない。
- Floating OriginはPresentationだけを移動し、絶対座標とレイヤーは変えない。
- 同じX/Yでも異なるレイヤーの占有、部屋、資源、個体、差分を混同しない。

## 4. Seedと生成バージョン

- 任意の数値・文字列Seedを受け付け、空欄は生成した文字列を表示する。安定した内部Seedへ変換する。
- 基礎生成はSeed、GeneratorVersion、保存した生成設定、レイヤー、絶対座標、用途別Salt、候補番号から決める。
- `UnityEngine.Random`、`string.GetHashCode()`、Transform、ロード順、Job完了順を乱数入力にしない。
- 用途別Saltを固定し、ブロック種類や装飾の追加で別用途の乱数列を消費しない。
- `AnimalPopulationSeed`は新規ワールドで一度だけ地形Seedと独立に生成して保存する。
- ワールド作成時のGeneratorVersion・設定をワールド全体に固定する。更新後の未生成チャンクにもその版を使う。生成済み・未生成チャンクを自動で新旧混在させない。
- サポートする旧生成器・設定解決を維持し、廃止が必要なら明示的な移行を別途設計する。
- 初期開発中は既存方針に従ってGeneratorVersion 1のまま調整できるが、開発用ワールドの互換性を保証しない。新旧データを誤って受理しないため、保存スキーマ識別・検証を技術仕様に従って持つ。
- `GeneratedWithVersion`はワールド版との整合を検証する用途に使える。旧`GenerationUpgradeEpoch`と境界ブレンディングは新計画に含めない。

## 5. バイオームとブロック構成

現在実装済みの7バイオーム、草原、森林、砂漠、岩地、湿地、雪原、火山は、TERRAIN-01Bで構成を再検討するまでの仮案とする。そこで各地域固有の探索・生態・採集体験、役割の重複、追加・統合・名称変更を比較し、安定IDと既存生成への影響を確認して正式な初期構成を合意する。比較候補の地上18バイオーム、水域17生息地、地域種プール、地上同士の隣接、水域の内包・海岸境界・深度遷移、初期スポーン規則、初回登場種、作物・牧場動物の入手地域は[バイオーム・生態コンテンツ仕様](./BiomeEcologyContentSpecification.md)に記録する。海は現時点では水域、海中・深海はWorldLayerであり、Biomeへ変更する場合もLiquid／水域種別、気候・天候、Blockとの責務を混同しない。生態の差はBiomeだけでなく、水域タグ・レイヤー・環境条件でも表現する。

- 気温、湿度、標高、Weirdness等から複数チャンクへ連続する領域を作る。既存の固定小数点ノイズと用途別Saltを再利用する。
- 基礎気温・基礎湿度はBiome IDから逆算せず、Seed、GeneratorVersion、保存設定、絶対座標から得る`ushort`の`0〜65535`を正とする。基礎気温は摂氏、基礎湿度は相対湿度%ではなく正規化された生成指数である。標高は同じ数値範囲の独立入力とする。
- 海面より高い標高に応じた寒冷補正を基礎気温から引き、`0〜65535`へ飽和させた地形気温を決定論的に導出する。補正は`floor(max(0, Elevation - SeaLevelThreshold) × 32,768 ÷ (65,535 - SeaLevelThreshold))`とし、64bit中間計算、整数切り捨て、飽和減算を使う。海面閾値`65,535`は設定エラーとして拒否する。Biomeを地形気温・基礎湿度・標高・水文・地質・海岸条件の分類結果として決め、標高補正を時刻・天候を含む現在気温で二重に適用しない。
- Biome定義は地形気温・基礎湿度の許容範囲と代表値を持てるが、代表値でセル固有の連続値を上書きしない。特殊Biomeへの分類後も基礎気温・地形気温・基礎湿度を保持する。
- 設定、UI、デバッグ表示、分布監査では、地形気温を極寒・寒冷・冷涼・温暖・高温、基礎湿度を極乾燥・乾燥・中湿・湿潤・過湿の各5段階へ分類する。段階は連続値から導出し、Biomeの許容範囲は複数段階へまたがることができる。開発者用表示では基礎気温と地形気温を別モードまたは同時情報として確認できるようにする。
- 地形気温の段階境界は`12,000`、`23,000`、`32,768`、`40,000`、基礎湿度の段階境界は`16,000`、`28,500`、`39,500`、`50,000`とする。各段階は下限以上かつ次の境界未満、最終段階だけ`65,535`以下として分類し、整数範囲の隙間・重複を作らない。
- 地上18バイオームの地形気温許容範囲は[バイオーム・生態コンテンツ仕様](./BiomeEcologyContentSpecification.md#24-バイオームごとの地形気温範囲確定)を正とする。気温範囲の一致だけで確定せず、湿度、標高、水文、地質、海岸条件との適合を要求する。湿原と火山は特殊条件を主とし、火山地熱で地域の地形気温を高温へ上書きしない。
- 地上18バイオームの基礎湿度許容範囲は[バイオーム・生態コンテンツ仕様](./BiomeEcologyContentSpecification.md#25-バイオームごとの基礎湿度範囲確定)を正とする。基礎湿度を土壌水分や水域の有無へ読み替えず、水文、地面Block、冠水、排水、灌水による局所状態と分離する。乾燥地域の局所水場は水域生息地として扱い、湿原Biomeへ無条件に変更しない。
- 標高は連続した`ushort`値を正とし、既定海面`20,000`では海面下`0〜19,999`、低地`20,000〜36,000`、平地・台地`36,001〜42,999`、山地`43,000〜53,999`、高山`54,000〜65,535`へ分類する。地上18バイオームの許容標高は[バイオーム・生態コンテンツ仕様](./BiomeEcologyContentSpecification.md#26-標高区分とバイオームごとの許容標高確定)を正とする。海面と区分境界は生成設定へ保存して順序を検証し、変更時はGeneratorVersionの互換性を判断する。
- 水域、岩壁、地面・壁Blockは標高区分と直交する地形状態とする。河川・池や岩壁へ分類したセルでも元の連続標高と標高区分を保持し、`Water`や`RockWall`で上書きしない。海底地形と水深は地上の標高区分へ含めず、WorldLayerと水域生息地の条件として扱う。
- Biome分類は[バイオーム・生態コンテンツ仕様](./BiomeEcologyContentSpecification.md#27-biome分類の処理順と決定論確定)の順序を正とする。気候・標高・地質と陸海を生成した後、集水・河川・湖・飽和土壌を求めてから最終地上Biomeを確定する。活動的な火山中核、水文特殊Biome、通常Biomeの順に判定し、通常候補は64bit中間値による整数適性、候補別の低周波変動値、安定Definition IDの順で一意に決める。
- 直接隣接禁止の上位2候補が設定されたスコア差以内なら、候補ペアに定義された適格な移行Biomeを選ぶ。近傍の生成済みBiomeを参照する後処理、チャンク生成順依存、候補なしの暗黙フォールバックは禁止する。上位候補、主要スコア、特殊判定・移行帯理由を開発者用監査へ公開する。
- 通常Biomeの適性比較には地形気温、基礎湿度、標高、木本植生ポテンシャル、地形起伏、地質、火山活動度、水文、海洋影響を使用し、同点解決だけにBiome別の低周波変動値を使う。各連続軸は`ushort`の`0〜65535`を正とし、専用Saltと再計算に必要な設定をワールドへ保存する。木本植生ポテンシャルを配置後の樹木数から、地形起伏を生成済み隣接チャンクから、海洋影響をロード済み範囲から逆算しない。
- 現在の天候・時刻・土壌水分、配置後の植物・Block・資源、初期スポーン距離、進行度、装備、隣接チャンクの確定Biomeは固定Biomeの分類入力にしない。既存`Weirdness`を火山活動度へ移行する場合は責務・Salt・GeneratorVersion・分布差を明示し、他用途と乱数列を共有しない。
- 通常Biomeの各連続軸は許容範囲と代表範囲を持ち、代表範囲内を`65,535`、許容範囲端を`0`として区間内を整数線形補間する台形型適性を使う。分類軸はBiomeとの組合せごとに`0〜65,535`の適合度を持つ。各Biomeの軸重み合計を`256`へ統一し、符号付き64bit以上の加重和で総合スコアを求める。許容範囲端の適性0は候補資格を失わず、全候補0点でも同点解決へ進む。
- 範囲順序、確定許容範囲との一致、重み合計、分類値の適合度を定義読込時に検証する。特殊Biome優先を巨大な加点で模倣せず、Biome変動値は完全同点時だけ使う。開発者用監査には候補資格、軸値、軸適性、重み、軸別積、総合スコア、同点解決段階を含める。
- 木本植生ポテンシャル、地形起伏、海洋影響、火山活動度は`0〜65,535`を`0〜13,106`、`13,107〜26,213`、`26,214〜39,320`、`39,321〜52,427`、`52,428〜65,535`の共通5段階へ分類する。段階は表示・設定・監査用であり、適性計算の連続値を置き換えない。実分布が各20%になるとは仮定しない。
- 地質はBiome別適合度を持つ分類値、水文は集水量・水系接続・冠水・飽和土壌を持つ複合状態として扱い、共通5段階へ変換しない。活動的な火山中核は適合する火山地質と火山活動度段階5の両方を最低条件とする。
- 木本植生ポテンシャルは既存Biome Warp後の座標へ、基準格子192タイル、3オクターブの192・96・48タイル、相対比重4：2：1、専用Saltで決定論的フラクタルノイズを適用して求める。基礎湿度を値へ合成せず、伐採・植林・配置結果から逆算しない。水文特殊条件を満たす低地では`39,321`以上を湿地林・沼沢林、未満を淡水湿原・氾濫原へ分ける。
- 地形起伏は対象セルの中心、上下左右16タイル、斜め11タイルの9点で標高の最大差を求め、`min(LocalRelief, 16,384) × 65,535 ÷ 16,384`を整数切り捨てして導出する。生成済み隣接チャンク、岩壁、Block、地域内の自動正規化を参照せず、固定オフセットの標高純粋関数だけを使う。座標加算と中間計算は64bit以上とし、対応範囲外を周回・飽和させない。
- 海洋影響は8方向を16・32・64・128タイルで調べ、標高が海面閾値未満の海サンプルだけから最短距離値と海方向数を求める。`floor((NearestSeaProximity + 3 × floor(SeaDirectionCount × 65,535 ÷ 8)) ÷ 4)`を海面以上セルの値とし、対象セルが海面未満なら表示用に`65,535`を返す。河川・池・湖、生成済みチャンク、探索範囲を参照せず、段階5を亜熱帯島嶼林の必須条件とする。
- 火山活動度は既存Biome Warp後の座標へ、基準格子256タイル、3オクターブの256・128・64タイル、相対比重4：2：1、専用Saltで決定論的フラクタルノイズを適用して求める。`SupportsActiveVolcanism`地質との組合せで、段階3を局所地熱現象、段階4を通常比較へ入る火山周縁候補、段階5を最優先の活動中核とする。自然露出マグマは段階5に限定するが、地質と形状条件を別途要求する。
- 既存`Weirdness`は旧GeneratorVersionで維持し、新しい火山活動度へ暗黙に改名しない。火山活動度、火山地質、マグマ形状は用途別Saltを分離し、活動度から基礎気温・地形気温・基礎湿度を上書きしない。
- `BiomeVariation`は既存Biome Warp後の座標へ、基準格子256タイル、2オクターブの256・128タイル、相対比重2：1で生成する。各Biome Definitionへ変更禁止かつ定義間で一意な64bit `VariationSalt`を明示し、完全同点の最高スコア候補群だけで変動値の最大を選ぶ。スコア差が1以上なら使用せず、移行帯判定を先に行い、変動値まで同点の場合だけ安定Definition IDの昇順で決める。変動値を総合スコアへ加算せず、初期スポーン・Biome出現・資源の保証には利用しない。
- `HydrologyState`は`uint CatchmentAreaCells`、複数指定可能な`ConnectionFlags`、`ushort NaturalFloodingPotential`、`ushort NaturalSoilSaturationPotential`、`NaturalSurfaceWater`からなる固定生成結果とする。流向・下流座標・河川グラフは水系生成データへ分離し、現在の降雨、河川水位、冠水、土壌水分、排水、灌水、人工水路から固定水文やBiomeを変更しない。湿原候補には低地、淡水接続、自然冠水または自然飽和をすべて要求し、海水接続だけ、小さな池、泉、オアシスだけでは広域湿原にしない。
- 水系は8×8タイルの水文セルとD8流向で生成する。水文セルは`floorDiv(WorldTile + 4, 8)`で区分し、中心からX・Yとも`-3`・`0`・`+3`の固定9地点の標高整数平均を代表標高とする。周囲8セルのうち代表標高が低いセル、次に同標高かつ専用Saltの安定順位が低いセルへだけ流し、流出先がなければ閉鎖流域候補にする。中心タイルが海面未満のセルを海洋流出口とし、D8流向を正としてタイル表示経路を後から細分化する。負座標、チャンク境界、ロード順、候補列挙順で結果を変えない。
- `CatchmentAreaCells`は8×8タイルの水文セルを1単位とし、対象セル自身の1と、D8グラフで直接流入する全上流セルの集水値を64bit以上で加算する。65,535で飽和させ、保存値65,535を「65,535水文セル以上」と解釈する。基礎湿度や降雨量を集水面積へ混ぜず、飽和後は値確定のための追加上流走査を行わない。反復集計とメモ化を許可するが、キャッシュ、集計順、Job順、ロード範囲によって結果を変えない。
- 同じ固定9地点の基礎湿度整数平均を`HydrologyMoisture`とし、D8上流からの合計を`65,535×65,535`で飽和させた後、65,535で割って`RunoffEquivalentCells`を得る。0〜15は一時流路候補、16〜127は`Stream`、128以上は`Stream`と`River`にする。流路へ細分化されたタイルだけを自然水面とし、上流湿度を合算して乾燥地を通る外来河川を維持する。湖・地下水・泉による恒久流は後続の水収支から追加できる。
- 同じ流向なしセルへ到達する4水文セル以上を閉鎖流域とし、流域境界で`max(内側代表標高, 外側代表標高)`が最小の安定した辺を越流点にする。末端を湖底、越流点を最大湖面とし、流出寄与8以上を固定湖候補、32以上を最大湖面・越流候補にする。充填率は`min(65,535, RunoffEquivalentCells×2,048)`とし、湖底から湖面未満で連続するセル・タイルだけを自然水面にする。越流辺は水域接続へ追加するが、元のD8流向と集水面積を変更しない。
- `GeologyClass`は未固結堆積物、砂岩、石灰岩、泥岩・頁岩・粘板岩、花崗岩質岩、変成岩、火山岩、超苦鉄質岩の8安定分類とする。各分類は透水性、地下水保持、侵食抵抗、カルスト適性、活動的火山適性を持ち、資源Definition側に地質適合度を持たせる。地質はBiomeやBlockの別名にせず、採掘・埋立・表面Block変更後も固定する。具体的な特性値と地域生成は[バイオーム・生態コンテンツ仕様](./BiomeEcologyContentSpecification.md#221-geologyclassの分類と責務確定)を正として段階的に確定する。
- 地質基礎値は共通5段階の中央値を使い、未固結堆積物を透水45,874・地下水保持58,981・侵食抵抗6,553、砂岩を45,874・45,874・32,767、石灰岩を58,981・45,874・45,874、泥岩等を6,553・19,660・32,767、花崗岩質岩と変成岩を19,660・19,660・58,981、火山岩を45,874・45,874・45,874、超苦鉄質岩を32,767・19,660・58,981とする。初回のカルスト適性は石灰岩だけ、活動的火山適性は火山岩だけに設定し、局所亀裂・粘土層・風化帯・帯水層は別補正とする。
- 地質地域は512×512タイルのマクロセルごとに、中心からX・Y各`-192〜+191`タイルずらしたサイトを置くジッターVoronoiで生成する。地質境界専用の256・128タイル、2：1、最大変位64タイルのX・Y座標ワープ後に、周囲5×5サイトの64bit以上の平方距離を比較する。±192ジッターでは3×3外が最近傍になり得るため探索を5×5とし、同距離はサイト座標とマクロセル座標の安定順で決める。地質境界、ジッター、クラス選択のSaltを他用途および相互で共有しない。
- 地質クラスの基礎重みは、未固結堆積物1,800、砂岩1,500、石灰岩1,200、泥岩等1,400、花崗岩質岩1,500、変成岩1,100、火山岩1,100、超苦鉄質岩400の合計10,000とする。サイト位置の海面下・低地・平地／台地・山地・高山区分ごとに確定した256基準の整数倍率を掛け、64bit以上の累積重みと偏りのない決定論的な有界整数選択でサイトごとに一度だけ抽選する。Biome、水文、資源、火山活動度をクラス抽選へ混ぜず、実面積率は複数Seedで監査する。
- 地下水涵養候補は固定9地点の基礎湿度、`RunoffEquivalentCells×2,048`、水文セル内の自然河川・渓流・固定湖候補の有無の最大とする。局所地質補正後の透水性と地下水保持の小さい方を帯水係数とし、涵養候補との積を65,535で整数除算して`GroundwaterPotential`を得る。32,768以上で`Groundwater`接続を設定するが、それだけで地表水面を生成せず、現在の降雨・灌水・人工水路・採掘穴を固定地下水へ混ぜない。
- 自然土壌飽和度は`floor((2×HydrologyMoisture + 2×GroundwaterPotential + (65,535-AdjustedPermeability) + (65,535-TerrainRuggedness)) ÷ 6)`で求め、39,321以上を自然飽和条件とする。低地、淡水接続、自然飽和または自然冠水を水文特殊Biomeの共通条件とし、現在土壌水分・灌水・排水・耕作・Block変更を固定飽和度へ戻さない。
- 自然冠水度は半径32タイル内の恒久淡水源から、距離・水面との比高・平坦さ・水域規模を2：2：1：1で整数合成し、39,321以上を自然冠水条件とする。低地・淡水接続・自然飽和または自然冠水を満たすタイルが8×8水文セル内に16以上あり、その候補セルが上下左右に4セル以上連結する場合だけ広域湿原候補にする。小成分は元Biomeへ局所水域生息地を重ねる。
- 湖候補は充填率を2、地下水と気候保持を各1で合成し、越流ありを恒久淡水湖、越流なしで水収支26,214未満を一時湖、26,214〜52,427を恒久塩湖、52,428以上を恒久淡水湖にする。一時湖は固定水面を残さず、塩湖は淡水接続・冠水源へ数えない。地下水域の低い縁では地下水を2、落差を1で合成して39,321以上を泉候補とし、32タイル内の最大候補だけから固定の淡水小川を生成する。
- 通常比較する15Biomeと火山周縁は、確定した地形気温・基礎湿度・標高・木本植生・起伏の代表範囲と、必要な海洋影響・火山活動度ゲートを持つ。軸重みはBiomeごとに合計256とし、気候型は気温・湿度・木本植生、高山岩地は標高・起伏、火山周縁は地質・活動度、島嶼林は海洋影響を主に評価する。水文特殊2Biomeは通常スコアへ含めず、具体値は[バイオーム・生態コンテンツ仕様](./BiomeEcologyContentSpecification.md#229-通常biomeの代表範囲と軸重み確定)を正とする。
- 18Biomeと8地質分類の組合せへ固定の地質適合度を定義する。通常Biomeでは地質だけで気候・標高適性を過度に逆転させない重みとし、水文特殊2Biomeの値はスコアへ加算しない。火山・地熱地帯は火山岩だけを適格とし、活動度段階4・5のどちらでも`SupportsActiveVolcanism`を必須にする。具体値は[バイオーム・生態コンテンツ仕様](./BiomeEcologyContentSpecification.md#230-biome別geologyclass適合度確定)を正とする。
- 直接隣接禁止の上位2候補は、最大Biomeスコアの6.25%に当たる差1,048,560以内で競合するときだけ移行帯判定へ進む。両方へ直接隣接でき、次点から同じ差以内にある第三の通常Biomeから最高スコアを選び、橋候補がなければ丸めず生成監査エラーにする。具体式と同点順は[バイオーム・生態コンテンツ仕様](./BiomeEcologyContentSpecification.md#231-禁止隣接ペアの移行帯確定)を正とする。
- GroundBlockはBiome別表層パレットと地質別露出基盤パレット、WallBlockは地質別自然壁パレットから選ぶ。パレット重みは各行256とし、表層64・32・16タイル、地質バリエーション32・16タイルの連続ノイズでパッチ化する。起伏・侵食抵抗・乾燥度から露出度を求め、39,321以上だけを基盤露出候補にする。具体的なBlock IDと重みは[バイオーム・生態コンテンツ仕様](./BiomeEcologyContentSpecification.md#232-groundblockwallblockパレット確定)を正とする。
- 現在気温、地域天候、土壌水分は基礎気候から分離する。時刻・天候・局所熱源、降雨・冠水・排水・灌水等で現在環境が変化しても、固定Biomeと基礎気候を変更しない。摂氏相当値への変換は現在環境・表示側で行い、浮動小数点の表示値を生成、保存、状態ハッシュへ戻さない。
- 同心円、初期地点からの距離、研究ランク、装備でバイオームを変えない。
- バイオームIDは固定の地域情報。地面や壁を別の素材へ置換しても変化しない。
- バイオームごとの地面・壁パレットと、地層・鉱床・局所パッチ用ノイズを分ける。1バイオーム1ブロックに固定せず、無関係なセルごとの市松抽選にもさせない。
- 木材・石材・鉄鉱石は地上18バイオームすべてに0より大きい通常生成重みを持たせ、[バイオーム・生態コンテンツ仕様](./BiomeEcologyContentSpecification.md#7-基礎資源と鉱物の初期配置計画)の`CoreResourceAuditWindow`単位で最低クラスタ数を監査する。初期スポーン探索の条件や開始地点専用の密度補正には使わない。
- 鉱床候補はBiomeだけから決めず、先に地質パレットと母岩適合を判定し、その後にバイオーム別密度係数、クラスタ形状、露出条件を適用する。地面・壁Blockと鉱床Definitionを別IDにし、鉱床を地形Spriteへ焼き込まない。
- 資源は生物由来、表層堆積、地質鉱床の3方式へ分け、地形Block Itemをクラフト資源へ数えない。地質依存24資源は8地質の固定適合度と256×256タイル当たりの基準クラスタ数を持ち、Biome係数と地質適合度を掛ける。通常鉱床は`LooseSurface`、`GroundEmbedded`、`WallEmbedded`を合算し、`MassiveDeposit`は別枠で生成・監査する。木材・石材・鉄鉱石の最低保証はそれぞれ24・32・24個以上とし、通常生成、保証追加、巨大鉱床を分けて監査する。具体値は[バイオーム・生態コンテンツ仕様](./BiomeEcologyContentSpecification.md#74-資源definitionの地質適合度確定)および[通常密度・最低保証](./BiomeEcologyContentSpecification.md#75-通常密度クラスタ数最低保証確定)を正とする。
- ブロック定義は定義GUID、硬度、回収アイテム、移動・設置・水密・施設境界属性、表示参照を持つ。
- TERRAIN-01Aの互換境界では、通常地面、自然岩壁、淡水、海水、マグマへ変更禁止GUIDを割り当てる。硬度・回収品・表示参照は後続機能で具体化し、未確定値を採掘量や見た目へ暗黙に流用しない。
- 境界の補間は座標由来の値から計算し、既に生成した隣接チャンクへ依存しない。
- 多層生成を追加しても、既存地上の結果を変える必要がない箇所は維持する。必要な変更は生成署名・分布監査・デバッグ表示の差として記録する。

## 6. 有効セルと編集

| データ | 寿命・責務 |
| --- | --- |
| バイオーム・自然環境 | Seedと座標から再生成。人工ブロックと分離 |
| GroundBlock | 掘削・埋立できる地面形態。なしなら空洞／穴 |
| WallBlock | 採掘・設置できる壁形態。地面とは別の占有だが、同材質のGround形態と回収Itemを共有 |
| Liquid | 地面がないセルの水種・マグマ。なしも許可 |
| Surface | 舗装、床、耕地などの表面状態 |
| 自然資源・植生 | 木、石、植物等の個別状態・生成差分 |
| 配置物 | 橋、扉、家具、設備等の独立状態・参照 |

これは論理データ境界であり、全セルを個別Entityにする要求ではない。Buffer・配列等の格納形式は計測で決める。

- 元生成結果を破壊せず、変更差分を適用して現在の有効セルを得る。元と一致する差分は除去できる。
- 変更差分は`WorldLayer＋論理チャンクX/Y`を所有キーとし、チャンク内セル番号順の疎な集合として保持する。同じX/Yの別Layerへ差分を流用せず、表示用生成チャンクのアンロードでも失わない。
- 差分の変更Maskで「未変更」と「明示的な区画除去」を区別する。変更後の区画構成と定義分類を検証してから差分を確定し、地面と液体の重複、地面のないSurface、分類違いの定義参照を拒否する。
- 移動判定と建築判定は有効セルを共通入力にするが、独立した結果を返す。自然資源・植生と配置物の占有は有効セルへ埋め込まず、Commandの上位検証で合成する。
- 自然生成壁・設置壁とも採掘可能で、必要道具硬度を検証する。各地形材質は共通`TerrainBlockItem`とGround／Wall両形態を持ち、地面・壁のどちらからも同じ材質Itemを1個回収する。
- 共通`TerrainBlockItem`をGroundBlockのない穴・液体セルへ置くとGround形態、GroundBlockがありWallBlockがないセルへ置くとWall形態になる。液体セルへの設置は同じCommandで液体を除去する。手動のGround／Wallモード切替は設けず、現在の有効地形から配置形態を一意に決める。
- WallBlock採掘後は下のGroundBlockを維持する。GroundBlock掘削後は穴になり、回収Itemは壁としても再配置できる。逆に壁から回収したItemも穴の埋立へ使える。WallBlockが残るセルのGroundBlockは直接掘削できない。
- WallBlockはGroundBlock上にだけ存在できる。GroundなしのWall、LiquidとGroundまたはWallの重複を有効セル検証で拒否する。
- Ground／WallのRuntime Definition、硬度、Sprite、通行・水密属性は別に保ち、安定材質IDと回収Itemで明示的に結ぶ。自然生成パレットに片方しか現れない材質も両配置形態を持つが、プレイヤー配置用の形態を自然生成パレットへ暗黙追加しない。
- `TerrainBlockItem`はGround／Wallの再配置専用で、クラフト材料タグを持たせない。石材、各種岩石、砂、粘土、鉱石等のクラフト資源はBlock Itemと別の資源Definition・Itemとして生成する。
- 初回41材質の材質ID・Ground形態・Wall形態・共通Itemの対応は[バイオーム・生態コンテンツ仕様](./BiomeEcologyContentSpecification.md#233-地形ブロックの回収再配置確定)を正とする。
- 地面を掘った空セルへ液体がなければ空の穴になる。同レイヤーの地面と液体を重複保持しない。
- 支えのない壁・設備、上層配置物のある地面・橋の変更などは、変更後の有効セルと依存関係をCommandで検証する。落下・崩落を暗黙に発生させない。
- 変更はアイテム消費・回収、耐久消費、占有、液体予定、施設・生態Dirtyを含め整合させる。失敗時は部分変更しない。
- 境界セルの編集は隣接サブチャンク・チャンクのハイライト、岩壁影、通行キャッシュにもDirtyを伝える。
- 未ロード隣接セルも、生成＋保存差分から読み取る。境界の見た目や生態で基礎生成だけを再サンプルして編集を無視しない。

## 7. 液体の伝播と反応

液体は有限の水量・水圧・流速を持つ物理流体ではない。穴が辺接続すると固定Tick上で伝播する。斜め接触だけを接続とするか等の細則はTERRAIN-02Aで固定する。

- 水1セルやバケツから広がり、取り出しても有限残量として枯渇しない。
- 埋立で当該セルの液体を除去し、再掘削時は空にする。近隣に液体があれば流入する。
- 水種の置換は明示的な全順序で、マグマとの接触は反応表で処理する。反応物、対象セル、競合時の順序を定義する。
- 自然生成の海とマグマの隣接は現行生成にもある。生成時の接触とプレイヤー操作後の反応をどう整合させるかを、無限反応・沿岸崩壊が起きない例で確認する。
- WorldLayerと絶対座標で安定した処理順を作る。処理予算を分割しても、同じ論理入力とTickから結果を再現可能にする。
- 未ロード先への境界要求・保留キューを保存し、表示のアンロードで伝播が消えたり永遠に止まったりしない。
- ただし無限世界全域を毎Tick生成しない。伝播の作業集合と予算、未生成領域の需要生成、過大処理時の継続方法を設計する。
- 睡眠やオフライン経過ではキューを消費しない。画面外でも稼働中SimulationTickで進める。
- 橋は液体を消さない。排水装置や水密扉は液体と部屋状態に明示的に関与する。

## 8. 多層水域

地上・海中・深海の同X/Yで隣接レイヤーへ移動する。入口オブジェクトは要求せず、固定保存IDと判定順は[WORLD-01B製品契約](../Development/World01BMultiLayerWaterContract.md)に従う。

WORLD-01Cでは`(WorldLayer, X, Y)`を座標、チャンク要求、動物位置、診断の検索キーへ接続した。自然地形GeneratorはSurfaceだけを処理し、Underwater／DeepSeaへ地上結果を複製しない。3層の自然Block・Liquid生成はTERRAIN-01A/Bの責務とする。

固定3層は論理的に常に存在し、未掘削セルは`Solid`として扱う。レイヤー移動は、遷移元・先の開放水域、移動先の通行・衝突、装備を検証する。単に地上セルが歩行可能という理由で海底の土や空気室へ通過させない。未ロード先も論理的には存在するが、レイヤーID、座標、隣接関係はロード状態に依存しないため先に検証する。構造的に妥当な移動先だけをロード／生成し、残る条件を再判定する。

川、池、沿岸を含む自然水域はUnderwaterまで水とする。DeepSeaは`WaterBodyType.Sea`のうち、Seed・GeneratorVersion・保存設定・絶対座標・用途別Saltから決定論的に選ぶ沖合だけに生成し、川・池には生成しない。沖合の具体的なノイズと閾値は自然3層生成の接続時に分布監査して決める。

地上から1階層掘ると同じX/YのUnderwater空間を作り、上層が水なら同じ固定Tickの移動判定前に自動浸水する。UnderwaterからDeepSeaを掘る場合も同じとする。通常の上下遮断は変更差分適用後の上層地面・下層天井から導出し、その後に閉じた水密配置物を合成する。独立した上下接続フラグは保存しない。上層を閉じても下層の既存水は消さず、排水施設が成立するまで保持する。

水密室は排水施設が成立している間、外水への水平扉を開けても乾燥を維持する。排水なしで開けば同じ固定Tickの移動判定前に浸水し、密閉だけでは既存水を除去しない。潜水・浮上は水同士に限定し、水中から直下の乾燥室へは移動しない。乾燥室へは同じレイヤーの水平扉から出入りする。排水設備の具体構成はFAC-02B、液体伝播の予算とキューはTERRAIN-02Aで決める。

プレビューは直下1層を簡略表示する。上の地面や不透明壁を透視せず、未発見生物の図鑑登録や遠隔操作を発生させない。描画のためのプレビュー常駐と、個体群・施設等のSimulation処理を区別する。

## 9. 開始地点の選択

- `BiomeDefinition.AllowInitialSpawn`相当の設定を開発者が変更できる。雪原・火山等を除外可能にする。
- 原点周辺から座標順・距離順など固定した優先順位で、地上の許可バイオーム内の有効地点を探す。
- プレイヤーの占有を満たす通行可能セルで、壁・液体・資源・設備内へ埋まらないことを検証する。
- コア、一定の平地面積、資源までの距離、低い敵密度・希少度は選択条件にしない。周辺に禁止バイオームがあることは許可する。
- 探索範囲を有限の段階で広げ、進捗を表示する。全バイオーム禁止、候補なし、座標限界では明示的な失敗として返す。Scene保存座標へゲーム開始するフォールバックは使わない。
- 選定した初期位置は保存し、ロード時に再探索しない。死亡時の救済は現在の地形を検証する。
- 旧12×8・中心3×3テストは歴史的な実装保証として扱い、変更PRで新条件のテストへ置換する。

## 10. 生物・植物・資源と環境

- 野生生物は固定Biome＋現在地形・液体・植物・明るさ・時間帯・天候・屋内等から候補を得る。
- 水域は地上Biomeを置き換えず、基底水域`Base`と構造・表面生息地`Overlay`へ分ける。同じ水セルには基底水域を一つだけ保持し、マングローブ、海草、ケルプ、サンゴ、海氷、深海サンゴ、熱水・冷湧水を条件が成立する基底水域へ重ねる。
- 水域生成は、地上Biome・標高、集水と水系、海岸基底水域、海底地形とWorldLayer、水温・塩分・流速・底質、構造生息地Overlayの順で行う。淡水から海水へは河口・汽水域を挟み、浅海から深海へは外洋表層・中層と大陸斜面・海底峡谷を挟む。
- 初期スポーンは乾いた`Surface`の通行可能セルだけを候補とする。水域までの距離では難易度や資源量を補正せず、装備なしで水域から離れられる連続した陸上経路を検証する。
- 同じBiomeに複数大陸の候補がある場合は、座標由来の連続した`RegionVariant`で野生生物、鳥類、植物、作物の候補を分ける。表示言語やチャンク生成順で地域種プールを変えない。
- 種×レイヤー×地域の収容数、現存数、回復・移入予定、抽選状態を保持する。現在の地域単位64×64は再利用候補とする。
- 永続個体と匿名遭遇を分け、個体群からの出現・退避と、捕獲・討伐による減少を別の会計にする。
- 捕獲済み・命名・追跡等は個体IDを維持する。表示のアンロードや時間帯変更で消失・再抽選しない。
- 回復は固定Tick上で進め、環境が回復すればゼロから再定着できる。睡眠で回復させない。
- 通常の敵の強さや出現を開始地点の距離、研究、工場規模で一律補正しない。未ロード拠点の構造破壊は発生させない。
- 木・植物は成長と種子等で増え、根を残した採集では再成長可能。鉱石・化石・地形ブロックは有限で再生成しない。
- 木材、露出石材、鉄鉱石は全地上バイオームに採取経路を持たせる。木材は樹木、木本低木、倒木、枯れ木、漂着流木、竹、ユッカ、ハイマツから得る。石材・鉱物はBlockと別の有限`GeologyDeposit`とし、Ground上の`LooseSurface`、Ground内の`GroundEmbedded`、Wall内の`WallEmbedded`、複数セルの`MassiveDeposit`へ分ける。前3形態は手動採掘、大型鉱床は後期の電力不要採掘設備へ接続する。
- `WallEmbedded`採掘はWall Block Itemと資源Itemを同じCommandで回収し、`GroundEmbedded`採掘はGroundを維持する。未採掘のGround鉱床を残した直接掘削を拒否し、プレイヤー設置Block、埋め戻し、自然Block復元から鉱床を新生・復活させない。
- `CoreResourceAuditWindow`の最低保証は通常抽選後の不足分だけを決定論的に補う。母岩・液体・占有条件を破って配置せず、適格セル不足は生成監査エラーにする。追加鉱物や表示順を増やしても、資源Definition IDごとの専用Saltにより既存資源の結果を変えない。
- 作物の種、苗、挿し穂、塊茎、株分け用の子株はモチーフ地域に対応する野生株・野生化株から入手できるが、入手後の栽培可否は現在環境と人工栽培設備で判定する。固定Biomeだけで移植を拒否しない。
- 設置ブロックは固定バイオームを変更しないが、飼育・栽培・生息条件を変更できる。

## 11. 読み込みと表示

現行の `Unrequested → Queued → GeneratingData → ReadyToApply → Active → Inactive → Unloaded` は表示・生成の段階として再利用する。`Active`は個体や工場の生存条件ではない。

- プレイヤーの移動・衝突・潜水先、カメラ表示、下層プレビュー、稼働施設・液体の要求を区別して集約する。
- 高速車両・ヘリを想定し、速度・方向に応じた先読みを計測する。未完成セルへ進入しない制御を用意する。
- カメラだけを遠くへ動かす診断操作で、図鑑や生態進行を獲得しない。
- 地形生成のJobと確定公開の固定Tick境界は現行の決定論保証を保つ。停止中の地形準備で個体群・IDを進めない。
- 現在の512タイル原点変更、先行表示1、生成プリロード1、保持余白1、同時生成2、反映消去4、プール8は既存カメラ検証時の値。車両・3層の合格値には流用しない。
- 通常速度12／高速36タイル毎秒は現行診断カメラの比較条件であり、歩行や車両の確定速度ではない。
- 土地16×24、岩壁16×28、論理セル16×16、液面8px投影、基準480×270を既存アート基盤として再利用する。新ブロックはBiomeではなくBlock定義から表示を選ぶ。
- 夜は照明の暗さで表現し、追加の視界半径制限を行わない。生物の発見判定と表示の視認性を一致させる境界を検証する。
- 表示の影・外周キャッシュは現在の有効地形を参照するよう更新する。元生成専用のHaloで編集済みの隣接壁を復元しない。

## 12. 保存

ワールドヘッダーはWorldId、Seed、GeneratorVersion、生成設定、初期位置、次回ID、SimulationTick、WorldClock、個体群Seed、地域天候の再現情報を持つ。

変更データはレイヤー＋チャンク＋サブチャンクで、地面、壁、液体、地表、除去済み資源、植生成長、配置物、液体保留要求を保存する。未変更地形は固定版で再生成する。表示・Halo・通行索引等は再構築する。

個体・個体群、施設、設備、物流、ドロップ、乗り物は所有者と安定IDに従い一度だけ保存する。跨ぐチャンクへ複製しない。プレイヤーの位置はレイヤー、整数セル、セル内連続位置を分けて保存する。死亡品の絶対消失Tickを保持し、未ロードで期限切れなら再生成しない。

## 13. デバッグと検証

実装変更と同じPRでEditor可視化、Map Viewer、凡例、中央タイル情報、分布監査、関連テストを更新する。新モードを追加しただけで既存通常表示が一致しない状態を完了にしない。

- F3/F4に現在レイヤー、絶対座標、初期位置を接続する。
- Editorで基礎生成／変更後地形、地面／壁／液体／穴、固定Biome、スポーン許可、通行能力別可否、液体キュー、生態収容数を確認できるようにする。
- Map Viewerは「自然生成」と「実ワールド差分込み」を明示し、未ロード差分を無視した自然生成を現在地形と誤表示しない。
- 同Seed・設定・Layer・座標の結果、異なる生成順、Job条件、チャンク境界、負座標、int端点を検証する。
- 編集→往復→保存→ロードで地形・資源・水・個体・IDが一致することを検証する。
- 全禁止スポーン、候補なし、初期地点に隣接する危険バイオームを確認する。周辺難易度を変えない。
- 水のない穴、埋立→再掘削、異種液体、反応連鎖、未ロード境界、予算分割、上下遷移失敗を検証する。
- 時刻ジャンプで地形・個体群回復・液体・死亡期限が進まないことを検証する。
- 表示のアンロードとSimulation稼働を分け、個体の重複、野生個体群の水増し、遠隔設備の停止を検出する。
- プレイヤー、動物、車両、3層プレビューを段階追加したDevelopment BuildでCPU/GPU/GC/メモリを計測する。製品最大Viewportや合格FPSを独自に設定しない。

具体的な現在のテスト・メニューは[テスト](../Development/Testing.md)と[Editorツール](../Development/EditorTools.md)を参照する。旧テストの成功は改訂後の未実装機能の検証済みを意味しない。
